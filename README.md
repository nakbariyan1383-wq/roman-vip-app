# اپ ساده رمان VIP (Flutter / Android)

این پروژه یک کلاینت نمایشی برای سایت **https://roman-vip.ir** است و API را از `https://roman-vip.ir/app-api.php` فراخوانی می‌کند.

## شروع سریع و ساخت APK

1. Flutter پایدار (stable)، Android Studio/Android SDK و Git را نصب کنید.
2. ZIP را استخراج کنید و پوشه `roman_vip_flutter_source` را باز کنید؛ یا همین فایل‌ها را در ریشه مخزن GitHub خود آپلود کنید.
3. در ترمینال، در ریشه پروژه اجرا کنید:
   ```sh
   flutter doctor
   flutter pub get
   flutter analyze
   flutter run
   ```
4. برای APK نهایی:
   ```sh
   flutter build apk --release
   ```
   فایل در `build/app/outputs/flutter-apk/app-release.apk` ساخته می‌شود. برای انتشار عمومی، APK باید با کلید امضای متعلق به خودتان امضا شود؛ این تنظیم/کلید عمداً در مخزن نیست.

## آپلود در GitHub و دریافت APK خودکار

1. در GitHub یک مخزن جدید بسازید. از **Add file → Upload files**، محتویات این پوشه را (نه خود پوشه تو در تو) بارگذاری و commit کنید؛ ریشه مخزن باید شامل `pubspec.yaml` و `lib/main.dart` باشد.
2. زبانه **Actions** را باز کنید و در صورت درخواست، workflowها را فعال کنید.
3. با هر push به `main`/`master` یا اجرای دستی workflow، تحلیل و ساخت انجام می‌شود. از اجرای workflow، بخش **Artifacts**، فایل `roman-vip-android-apk` را دانلود کنید.
4. برای ایجاد GitHub Release، یک tag مثل `v1.0.0` بسازید و push کنید:
   ```sh
   git tag v1.0.0
   git push origin v1.0.0
   ```
   workflow APK را به Release همان tag پیوست می‌کند. نسخه عمومی را ابتدا با حساب Play Console و کلید امضای امن خود منتشر کنید.

## API و رفتار برنامه

- درخواست‌ها فقط HTTPS هستند، با POST و فرم `application/x-www-form-urlencoded` (کتابخانه `http` وقتی `Map` می‌گیرد فرم را encode می‌کند).
- درخواست فهرست: `action=get_novels`. برنامه پاسخ JSON را می‌خواند و آرایه‌های متداول `novels`، `posts`، `data` یا `items` را می‌پذیرد؛ برای هر رمان نیز `title/name/post_title`، توضیحات، تصویر و پیوند را از نام‌های متداول می‌خواند. تصویر فقط اگر URL معتبر HTTPS داشته باشد بارگذاری می‌شود و در خطای شبکه placeholder نشان می‌دهد.
- ورود: `action=login` به‌همراه `username` و `password`. ثبت‌نام: `action=register` به‌همراه `username`، `password` و `email` (اختیاری). چون قرارداد دقیق فیلدها/ساختار JSON در فایل مرجع موجود نبود، این نام‌ها فرض اولیه‌اند؛ آن‌ها را با پیاده‌سازی واقعی `app-api.php` تطبیق دهید. خطاهای HTTP، JSON نامعتبر و پیام خطای JSON نمایش داده می‌شوند.
- حالت کاربر فقط تا زمان بسته‌شدن برنامه در حافظه نگه داشته می‌شود؛ گذرواژه و توکن جعلی ذخیره نمی‌شود. این API ظاهراً توکن نشست مستندشده‌ای ارائه نکرده است؛ بنابراین این ورود را احراز هویت امن/پایدار تلقی نکنید.
- دو زبانه PDF تمام‌شده و آنلاین، نمایش نمایشی هستند. API فعلی فقط post برمی‌گرداند و متادیتای قطعی نوع/وضعیت PDF ندارد؛ برچسب PDF/تمام‌شده صرفاً با تطبیق متن و دسته‌بندی‌های در دسترس شناسایی می‌شود و موارد دیگر در آنلاین می‌آیند.
- انتخاب رمان صفحه‌ی `permalink` امن سایت را در مرورگر باز می‌کند. خرید/checkout و دسترسی محتوا در سایت باقی می‌ماند. **هیچ پرداخت، حق دسترسی PDF یا Premium در این اپ پیاده‌سازی نشده است.**
